# ヨルグラ アップローダー

FiveM サーバー「ヨルグラ」用の画像アップローダーです。
ブラウザに画像をドロップすると [fivemanage](https://fivemanage.com/) の画像ホストへアップロードし、
Discord やゲーム内で貼れる共有 URL を発行します。

旧 TSP 時代のアップローダーの置き換え版です。**依存ライブラリなし・`index.html` 1枚だけ**で動作し、
GitHub Pages などの静的ホスティングにそのまま置けます。

---

## できること

| レーン | 処理内容 |
|---|---|
| ① 高さ300pxにリサイズ | 縦 300px に縮小して PNG で送信。**透過を保持**するのでロゴ・バナー向け |
| ② 縦横125pxに統一 | 比率を保ったまま **125×125px の正方形キャンバス**に中央寄せで収める。余白は透明・PNG 出力。アイテムアイコン向け |
| ③ 画質を圧縮 | 解像度はそのまま JPEG 化（品質 0.7）。1MB を超える場合は品質を 0.1 刻みで下げて再試行（下限 0.3） |
| ④ GIFをそのまま | 無変換で送信。アニメーションが壊れません |
| ⑤ 無加工でアップ | 元ファイルをそのまま送信 |

その他:

- 複数ファイルの同時アップロード対応
- ドラッグ&ドロップ / クリックしてファイル選択 の両対応
- **`Ctrl` + `V` でクリップボードの画像を直接アップロード**（既定では③圧縮レーン扱い。GIF は自動的に④へ回ります）
- 20MB を超えるファイルは送信前に拒否
- 結果一覧にサムネイル・URL・「コピー」ボタン。URL クリックで新規タブ表示
- アップロード履歴は**ページ内のみ**（リロードすると消えます。どこにも保存しません）

## 使い方

1. 公開された URL（GitHub Pages のアドレス）を開く
2. 初回のみ「APIキー設定」に fivemanage の**画像用 API キー**を貼り付けて「保存して開始」
   - 「この端末に保存する」**ON** → ブラウザの localStorage に保存（次回から入力不要）
   - **OFF** → sessionStorage に保存（タブを閉じると消える。**共用PC・配信中はこちら**）
3. 使いたいレーンに画像をドロップ

キーを入れ替えたいときは「キー変更」、端末から消したいときは「キー削除」を押してください。

---

## APIキーの入手方法

1. <https://fivemanage.com/> にログイン
2. ダッシュボードから対象サーバー / プロジェクトを選択
3. トークン（API Keys / Tokens）の発行画面を開く
4. **画像用（Images）のトークン**を発行してコピー
   - ログ用やファイル用のトークンでは画像アップロードは通りません（401 が返ります）
5. コピーした文字列をアップローダーの「APIキー設定」に貼り付ける

> キーはサーバーの管理者が発行し、利用者へ個別に配布する運用を想定しています。

## GitHub Pages へのデプロイ手順

1. GitHub で新規リポジトリを作成する（例: `yorugura-uploader`）
   - Public で問題ありません（**キーはソースに入っていないため**。理由は下の「セキュリティ設計」参照）
2. このフォルダの中身を push する
   （このフォルダは QBCore リポジトリの中にあるため、**一度リポジトリ外へコピーしてから** `git init` すること。中で直接 init すると入れ子リポジトリになります）

   ```bash
   mkdir C:\Temp\yorugura-uploader
   copy C:\FXServer\txData\QBCore_FE08AD.base\_dev\YoruguraUploader\* C:\Temp\yorugura-uploader\
   cd C:\Temp\yorugura-uploader
   git init
   git add index.html README.md
   git commit -m "ヨルグラ アップローダー 初版"
   git branch -M main
   git remote add origin https://github.com/<ユーザー名>/<リポジトリ名>.git
   git push -u origin main
   ```

3. GitHub のリポジトリページ → **Settings** → 左メニュー **Pages**
4. **Source** を `Deploy from a branch`、**Branch** を `main` / `/ (root)` に設定して **Save**
5. 1〜2分待つと `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

`index.html` はリポジトリ直下に置いてください（Pages がトップページとして読み込みます）。
更新するときは `index.html` を編集して push するだけで自動的に再デプロイされます。

## セキュリティ設計 — なぜ APIキーをソースに書かないのか

### 旧版の問題

旧 TSP 版はページの JavaScript に fivemanage の API キーが**平文でハードコード**されていました。

GitHub Pages に置いたページの JS は、**ブラウザの「ページのソースを表示」や DevTools で誰でも読めます**。
静的サイトに「隠す」場所は存在しません。難読化しても、ブラウザが実行できる=読めるので同じことです。
GitHub リポジトリが Public ならソースコードとしても直接読まれます。

漏れたキーで第三者にできてしまうこと:

- 勝手に画像をアップロードされる（**アップロード枠・ストレージ容量の食い潰し**）
- 違法・不適切なコンテンツをサーバー名義のホストに置かれ、**サーバー運営の責任問題になる**
- 大量アップロードによる fivemanage アカウントの凍結・課金増

### 新版の対策

- **キーはソースコードに一切含まれていません。** 各利用者が初回に自分で入力します。
- 入力されたキーはブラウザの localStorage / sessionStorage に保存されるだけで、
  fivemanage の API 以外へは送信されません（サーバーサイドもトラッキングもありません）。
- 入力欄は `type="password"`。設定後は先頭4文字のみのマスク表示になります。
- 送信先は `https://fmapi.net/api/v2/image` に固定。UI からエンドポイントを変更する手段はありません
  （キーを別サーバーへ送らせる細工を防ぐため）。
- 401 / 403 が返った場合は「APIキーが無効です」と表示し、キー設定パネルを再表示します。

### ⚠️ 旧キーのローテーション（重要）

**旧 TSP 版に埋め込まれていた API キーは、公開ページ上で全世界に露出済みです。**
新版に移行しただけでは旧キーは有効なままなので、
**fivemanage のダッシュボードで旧トークンを失効（Revoke / Delete）し、新しいトークンを発行し直してください。**
新トークンを各利用者に配布し、旧版のページは公開停止（リポジトリ削除または Pages 無効化）することを推奨します。

## 運用上のメモ

- **キーは利用者ごとに各自入力する運用**です。ページ側は誰のキーも保持していないため、
  「ページを開いただけでは何もアップロードできない」状態が正常です。
- 共用 PC や配信中の画面では「この端末に保存する」を**オフ**にしてください。
- ブラウザのシークレットモードでは保存が効かない場合がありますが、その場合もタブを開いている間は動作します。
- 圧縮レーンは JPEG 化のため**透過が白で塗り潰されます**。透過を残したい画像は①リサイズ・②125px統一・⑤無加工を使ってください。
- 圧縮の目標は 1MB、下限品質は 0.3 です。元画像が極端に大きい場合は 1MB を超えたまま送信されることがあります。

---

## 旧版からの主な変更点

- APIキーのハードコードを廃止し、利用者入力＋ブラウザ保存方式に変更
- ②「縦横125pxに統一」・⑤「無加工でアップ」レーンを追加
- `Ctrl` + `V` 貼り付けアップロードに対応
- GIF レーンのレスポンス解析バグを修正（旧版は `data.url` を直接見ており、常に失敗していた）
- 圧縮処理を修正（旧版は `image/png` で品質引数を指定しており、PNG では品質引数が無視されるため実際には圧縮されていなかった）
- 20MB 超の事前拒否、複数ファイル対応、URL コピーボタン、ヨルグラ（夜空グラデ）テーマの UI
